# Нагрев: чем мерить и что уже найдено

Телефон грелся в покое — при пустом экране и без единого касания.
Причина оказалась не там, где я её искал, и нашлась только измерителем.

## Чем мерить

В пульсе печатается занятость каждого ядра за последние десять секунд:

```
ЗАНЯТО ЯДЕР %: 0 0 0 0 0 0 | 0 0 (A75)
```

Устроено просто. Тик таймера приходит сто раз в секунду независимо ни от
чего, и в `sched_tick` видно, какая задача застигнута на ядре. Если
холостая — считаем тик в `idle_ticks`. Отношение одного счётчика к
другому и есть доля занятости. Ничего измерять отдельно не нужно.

Ядра не одинаковые: по дереву устройства с нулевого по пятое —
Cortex-A55, шестое и седьмое — Cortex-A75. Большие греются заметно
сильнее при той же занятости, поэтому в отчёте они отделены чертой.

### Оговорка, о которую стоит не споткнуться

Мера здесь — **«на ядре не холостая задача»**, а не «ядро действительно
работает». Задача, вызывающая `wfi` у себя внутри, засчитается занятой
на все сто, хотя ядро при этом стоит.

Это не придирка: ровно так и выглядел главный виновник. Если однажды
число покажется несуразным — искать надо здесь.

## Что нашлось

### Пульс держал целое ядро круглые сутки

В цикле задачи-отчёта стояло:

```c
if (sec == last_sec) {
    wfi();          /* до ближайшего прерывания делать нечего */
    continue;
}
```

`wfi` останавливает ядро до ближайшего прерывания и потому выглядит
безобидно. Но оно **внутри задачи**, а задача при этом не уступает: для
планировщика она всё время готова, холостая задача на это ядро не встаёт
никогда, и глубже дремоты ядро не уходит.

Измеритель показал ровно одно ядро на ста процентах, и занятость
переезжала с ядра на ядро **вместе с пульсом** — совпадение проверено по
логу дважды. Лечится заменой на `task_sleep_ms(1000)`: задача снимается
с ядра совсем.

Проверка после правки: все восемь ядер на нуле, а кванты пульса упали с
880 до 51 за тот же промежуток.

### Задачи счёта дрались за общий замок

Их десять, каждая двадцать раз в секунду берёт **общий** замок тысячу
раз — двести тысяч захватов в секунду, и все восемь ядер дерутся за одну
строку кэша. Работа при этом бесполезная: задачи заведены, чтобы
показать планировщик и замки.

Пауза между кругами у них была с самого начала, и этого мало: между
паузами они всё равно молотят. Теперь они останавливаются через двести
кругов — десяти секунд с избытком хватает, чтобы расхождение счётчиков
вылезло, если оно есть.

## Что осталось

Процессор как источник тепла закрыт: в покое ноль на всех ядрах. Дальше
источники не процессорные, и мерить их надо иначе.

- **Слой 0 оверлея во весь экран.** Контроллер читает 1080×2340 каждый
  кадр, плюс слой 2 — порядка двадцати мегабайт за кадр, больше
  гигабайта в секунду постоянного чтения из памяти. Реально от слоя 0
  видны только полосы сверху и снизу, 96 и 48 точек.
- **Два A75 при нулевой нагрузке.** Включены и просто текут.
- **Опрос тачскрина.** Сто пробуждений в секунду не дают ядрам уйти в
  глубокий сон.
- **Частота ядер.** Мы её не трогали — там то, что оставил загрузчик.
  При нулевой занятости это уже вторично.
