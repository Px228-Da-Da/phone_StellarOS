# Hittis — язык приложений StellarOS

Справочник по языку. Про то, зачем он устроен именно так и как приложение
попадает в телефон, — [05-hittis.md](05-hittis.md).

Всё, что здесь написано, проверено по `hittis/hittis.c` (компилятор) и
`hittis/vm.c` (машина). Если справочник и код разойдутся — прав код, а
справочник надо чинить.

---

## Программа целиком

```
# Первое приложение: считает касания и рисует полосу.

app "СЧЁТЧИК" 600 400

фон   = 0xFF0B1020
белый = 0xFFFFFFFF
синий = 0xFF4C8DFF

def полоса(сколько):
    ширина = сколько * 20
    if ширина > 560:
        ширина = 560
    rect(20, 200, ширина, 40, синий)

счёт = 0
живём = 1

while живём:
    rect(0, 0, 600, 400, фон)
    text(20, 40, 4, белый, "КАСАНИЙ")
    textn(400, 40, 4, синий, счёт)
    полоса(счёт)
    show()

    касание = touch()
    if касание < 0:
        живём = 0
    else:
        счёт = счёт + 1
```

Собрать и посмотреть, не трогая телефон:

```
make -C hittis
hittis/hittis apps/счётчик.ht /tmp/счётчик.slt
hittis/hostrun /tmp/счётчик.slt
```

## Строки и отступы

**Комментарий** — от `#` до конца строки.

**Блоки задаются отступами**, как в Python. Табуляция считается за четыре
пробела. Отступ блока должен быть строго больше отступа заголовка, а все
строки одного блока — с одинаковым отступом; иначе компилятор скажет
«отступ не совпадает ни с одним уровнем».

Пустые строки и строки из одного комментария не значат ничего: на уровень
блока они не влияют.

---

## Значения

**Целые числа, 64 бита со знаком.** Больше в языке нет ничего.

Ни дробных, ни логических, ни массивов, ни строковых переменных. Ложь —
это `0`, истина — всё остальное; сравнения дают `1` или `0`.

Числа пишутся десятичными (`120`) или шестнадцатеричными (`0xFF4C8DFF` —
так удобнее задавать цвет).

**Число в исходнике — от 0 до 4294967295** (`0xFFFFFFFF`): команда
«положить число» несёт четыре байта. Отрицательных литералов в языке нет
вовсе — `-5` это «пять» и смена знака отдельной командой, поэтому старший
бит четырёх байт принадлежит числу, а не знаку, и `0xFF4C8DFF` — это
4283207167, а не отрицательное. Число больше компилятор не примет:
молча обрезанная константа даёт программу, которая честно работает и
выдаёт неверный ответ, а ищется такое часами.

**Считать при этом можно шире**: во время работы всё считается в 64
битах, и `65536 * 65536` даст ровно 4294967296.

**Строки существуют только как литералы** — их можно передать в `print`
или `text` и больше ничего: ни сложить, ни сравнить, ни положить в
переменную. Экранирования внутри кавычек нет: строка идёт до ближайшей
закрывающей кавычки.

## Имена и переменные

Имя начинается с буквы или `_` и может содержать буквы, цифры и `_`.
**Русские имена разрешены**: всякий байт со старшим битом считается
буквой, поэтому `счёт`, `плитка`, `горит` — обычные имена.

Переменная заводится первым присваиванием, объявлять её отдельно не надо:

```
счёт = 0
счёт = счёт + 1
```

**Область видимости — две, и правило простое:**

| Где | Что делает присваивание | Что видит чтение |
|---|---|---|
| на верхнем уровне | заводит **глобальную** | глобальные |
| внутри `def` | заводит **местную** | сначала местные, потом глобальные |

Отсюда следствие, о которое легко споткнуться: **функция не может
изменить глобальную**. Присваивание внутри `def` всегда заводит свою
местную переменную, даже если глобальная с таким именем есть. Читать
глобальные функция может свободно — так и задуманы цвета и размеры из
примера выше.

Чтобы функция что-то вернула наружу, у неё есть `return`.

## Операции

От слабых к сильным:

| Уровень | Операции | Замечание |
|---|---|---|
| 1 | `or` | |
| 2 | `and` | |
| 3 | `< > <= >= == !=` | результат `1` или `0` |
| 4 | `+ -` | |
| 5 | `* / %` | целочисленное деление |
| 6 | `-x`, `not x` | |
| 7 | `( )`, вызов | |

Все двухместные операции левоассоциативны. `and` и `or` **не** сокращают
вычисление: оба края считаются всегда — в языке нет ничего, у чего
вычисление имело бы побочный смысл, кроме вызовов, а их лучше писать
отдельной строкой.

Деление и остаток от нуля — не молчаливый ноль, а остановка приложения с
жалобой.

---

## Ветвление

```
if условие:
    ...
else:
    ...
```

`elif` нет. Несколько условий подряд пишутся вложенно:

```
if n < 0:
    цвет = серый
else:
    if n > 2:
        цвет = серый
    else:
        цвет = синий
```

## Цикл

```
while условие:
    ...
```

Другого цикла нет, `break` и `continue` тоже нет. Выход из цикла —
переменная-признак (`живём = 0` в примере) или `return`, если цикл внутри
функции.

---

## Функции

```
def имя(а, б):
    ...
    return значение
```

- аргументы — только имена, без значений по умолчанию;
- `return` без значения возвращает `0`; функция без `return` тоже
  возвращает `0`;
- **функцию можно вызвать раньше, чем она определена**: компилятор
  сначала находит все `def`, и только потом разбирает тело;
- рекурсия работает, глубина вызовов — 32;
- вложенных функций нет; `def` пишется на верхнем уровне.

Имена встроенных вызовов сильнее своих: если назвать функцию `text`,
вызываться будет встроенный вывод текста, а не она.

## Что можно попросить у системы

Тринадцать вызовов — это вся дверь наружу. Ни памяти, ни устройств, ни
файлов иначе приложение не видит.

| Вызов | Что делает |
|---|---|
| `print(строка)` | напечатать строку в консоль |
| `printn(число)` | напечатать число в консоль |
| `window(ш, в)` | попросить окно; обычно не нужен — окно даёт заголовок `app` |
| `rect(x, y, ш, в, цвет)` | закрасить прямоугольник |
| `text(x, y, кегль, цвет, строка)` | написать строку |
| `textn(x, y, кегль, цвет, число)` | написать число |
| `show()` | показать нарисованное |
| `touch()` | дождаться касания |
| `sleep(мс)` | поспать |
| `time()` | сколько система работает, миллисекунд |
| `width()`, `height()` | размеры своего окна |
| `exit(код)` | завершиться |

Всё рисование ложится в невидимую половину окна, и на экране появляется
только после `show()`. Половины система меняет местами целиком, поэтому
наполовину нарисованного кадра не бывает — мигания в приложениях на
Hittis нет по устройству, а не по старанию.

**Цвет** — `0xAARRGGBB`. Прозрачность обязана быть `FF`: `0x00FFFFFF` —
это полностью прозрачный белый, то есть ничего.

**Кегль** — это множитель восьмипиксельной клетки: `2` даёт 16 пикселей,
`3` — 24, `4` — 32, `6` — 48. Ближайшее готовое начертание система
подберёт сама (см. [06-font.md](06-font.md)).

## Касание

`touch()` ждёт, пока экрана коснутся, и возвращает **одно число**: у
машины нет ни структур, ни возврата нескольких значений. Разбирается оно
делением и остатком:

```
млн = 65536 * 65536                  # 2 в 32-й

касание = touch()
if касание < 0:
    живём = 0                        # касаний больше не будет
else:
    действие = касание / (млн * 65536)   # 0 нажали, 1 ведут, 2 отпустили
    x = (касание / млн) % 65536
    y = касание % млн
```

Координаты приходят **в координатах вашего окна**, а не экрана: где окно
стоит на экране, приложение не знает и знать не должно.

Ведение пальцем система склеивает: пока приложение рисовало кадр, палец
прошёл десяток точек, и все они, кроме последней, устарели. Приложение
получает то, где палец сейчас, а не всю его дорогу.

## Заголовок приложения

```
app "ПЛИТКИ" 720 900
```

Имя видит система, размеры — какое окно просить. Строка необязательная:
без неё приложение останется без имени и без окна (для тех, кому нужна
только консоль). Размер — просьба, а не приказ: больше экрана окна не
дадут.

## Когда что-то не так

**Компилятор** называет строку и причину и ничего не собирает:
«переменная не определена», «неизвестная функция», «не столько
аргументов», «строка не закрыта кавычкой», «отступ не совпадает ни с
одним уровнем».

**Машина** проверяет приложение на каждом шаге и при нарушении
останавливает его с внятной жалобой — не портя ни чужую память, ни
систему:

- деление на ноль, остаток от деления на ноль;
- переход за границу кода, вход функции за границей кода;
- вызов несуществующей функции, неизвестная команда;
- обращение к ячейке, глобальной или строке за границей;
- переполнение стека значений, слишком глубокая вложенность вызовов;
- не хватило места под переменные.

Это не перестраховка: `.slt` приходит из файла, его мог испортить кто
угодно, и «оно же само себе не враг» здесь не работает.

## Пределы

| Что | Сколько |
|---|---|
| Байткод одного приложения | 64 КБ |
| Строки | 8 КБ |
| Функций | 128 |
| Глобальных | 256 |
| Стек значений | 256 |
| Глубина вызовов | 32 |
| Ячеек под все кадры вызовов | 1024 |
| Имя приложения | 31 байт |

Пределы небольшие намеренно: машина не выделяет памяти вовсе — всё лежит
в одной структуре, которую даёт вызывающий. На телефоне это важнее
всего, там просить память не у кого.

## Как проверяется этот справочник

`apps/проверка.ht` — не приложение, а список утверждений отсюда,
переписанный на самом языке: приоритет операций, целочисленное деление,
области видимости, рекурсия, сравнения, циклы, шестнадцатеричные числа.

```
hittis/hittis apps/проверка.ht /tmp/п.slt && hittis/hostrun /tmp/п.slt
```

Каждая строка «СХОДИТСЯ» — одно проверенное утверждение справочника,
«НЕ СХОДИТСЯ» — разошедшееся. Проверка окупилась в первый же запуск: она
нашла, что старший бит числа считался знаком, и цвет `0xFF4C8DFF`
приезжал отрицательным.

## Чего в языке нет

Массивов, строковых переменных, дробных чисел, структур, ссылок,
`elif`, `for`, `break`, вложенных функций, модулей.

Это не список планов. Язык задуман под приложения с интерфейсом:
нарисовать, дождаться пальца, посчитать, нарисовать заново. Всё, что не
нужно для этого, добавляется только тогда, когда без него перестанет
получаться настоящее приложение, — и первым в очереди стоит массив, без
которого не написать список.
