# Как загружается MediaTek MT6769 и куда встраиваемся мы

```
[BROM]         ПЗУ внутри чипа, неубиваем. Ищет preloader на eMMC.
   |           Если не находит / зажаты Vol-+Vol+ → режим BROM (спасение через USB)
   v
[preloader]    раздел `preloader`. Инициализирует DRAM (самая сложная часть,
   |           калибровка таймингов LPDDR4X). Дальше грузит ATF+LK.
   v
[ATF / BL31]   ARM Trusted Firmware, живёт в EL3. Остаётся в памяти навсегда.
   |           Даёт нам PSCI: включение остальных 7 ядер, reset, power-off.
   v
[LK]           Little Kernel — «бутлоадер» в понимании пользователя. Раздел `lk`.
   |           Рисует splash, реализует fastboot, инициализирует MIPI DSI панель
   |           и оставляет включённым фреймбуфер (continuous splash).
   |           Читает раздел `boot`, проверяет подпись (если залочен),
   |           распаковывает ядро и DTB, прыгает на точку входа ядра в EL1/EL2.
   v
[ЯДРО]  <---- ЗДЕСЬ МЫ. Раздел `boot`, формат Android boot.img v2.
```

## Что нам дарит LK — и это ключ ко всему

1. **DRAM уже инициализирована.** Самую сложную часть за нас сделал preloader.
2. **Дисплей уже включён и работает.** LK настроил MIPI DSI панель и показывает
   логотип. Фреймбуфер остаётся живым. Нам НЕ нужно писать DSI-драйвер, чтобы
   вывести первую картинку — достаточно писать пиксели в память фреймбуфера.
3. **PSCI доступен** через инструкцию `smc` — так поднимаем остальные ядра.
4. **Указатель на DTB в регистре `x0`** — оттуда читаем карту памяти,
   адрес фреймбуфера, адрес UART.

## Протокол входа в ядро AArch64 (Linux boot protocol)

LK передаёт управление так:
- `x0` = физический адрес DTB (flattened device tree)
- `x1..x3` = 0
- CPU в EL2 (или EL1), MMU **выключен**, кэш данных **выключен**, прерывания замаскированы
- Работает только загрузочное ядро (CPU0), остальные 7 спят в ATF
- Образ должен начинаться с 64-байтного **Image header** с магией `ARM\x64`

Всё это реализовано в `kernel/src/boot.S`.

## Формат раздела boot

Android boot.img v2: заголовок 4096 байт + kernel + ramdisk + second + dtb.
Нам нужен только kernel. Собирается `tools/mkboot.sh` через `mkbootimg`
с параметрами, снятыми с оригинального boot.img (`unpack_bootimg`), — чтобы
base/offset/cmdline совпадали с тем, что ждёт LK.
